# Shared key-graph schema migration

`deploy.KeyGraphMigration` renders the version 3 PostgreSQL deployment script.
Like the earlier migrations, it is an explicit DBA deployment artifact. Runtime
workspace connections do not apply DDL. The script requires the exact workspace
UUID, role tag and schema version 2, locks the workspace metadata with `NOWAIT`,
and executes under the private owner role with fixed search path and timeouts.
DDL and the schema-version update commit together; any error rolls everything
back. Reapplying the migration is rejected.

The migration adds four private tables:

- `keys`: versioned identities and public certificates, with the issue's key-kind
  allowlist and one active key per kind/owner. Encryption and signing keys remain
  separate rows. Certificate signer ID, version and signature must be supplied
  together and reference an existing key. Pending keys permit staged rotation.
- `key_copies`: copied key, holder and issuer references, suite, encapsulation,
  ciphertext and signature. A key cannot hold its own identical version. Deleting
  a copied key cascades to its copies; holder/issuer references remain restrictive.
- `secret_values`: owner kind/ID/field, DEK reference, encrypted envelope and row
  version. A referenced DEK cannot be deleted while a secret still uses it.
- `invites`: target user, invite/reset kind, 32-byte code hash, creator, finite
  creation/expiry/usage times, attempts, distinct bootstrap encryption/signing key
  references and an opaque encrypted bootstrap envelope. No plaintext code column
  exists. Expiry must follow creation; a usage timestamp must lie in that interval.
  The signed graph manifest is bounded at 1 MiB, has a positive revision, and its
  digest is generated by PostgreSQL's built-in SHA-256 function for commit checks.

All key versions use positive PostgreSQL integers. IDs representing keys, owners
and invites reject the nil UUID; row versions are positive. Byte lengths are
bounded: public keys and encapsulations at 4096 bytes, signatures at 64 bytes,
key-copy ciphertext at 4 MiB plus an AEAD tag, secret envelopes at 8 MiB and
bootstrap envelopes at 64 KiB. These storage bounds accommodate versioned
formats; native cryptographic operations impose their narrower suite-specific
constraints, such as the 48-byte HPKE ciphertext for a 32-byte key.

No table access is granted to public, user or admin roles. Future versioned
security-definer APIs must enforce authorization and validate record kinds,
certificates, suites and ciphertext before publication. SQL shape constraints
do not verify signatures, authenticate key ownership, prove an invite hash was
derived correctly, or prevent a privileged owner from resetting `used_at`.
Single-use redemption, atomic replacement-set comparison, verifier updates and
audit remain enrollment API work. This migration does not mark a workspace ready
or enable Join.

Real PostgreSQL tests cover wrong identity/version, a contended metadata lock,
late DDL failure with complete rollback, replay rejection, client table denial,
active-key uniqueness, pending-key staging, certificate consistency, reference
integrity, self-copy rejection, invalid byte lengths, invite lifetime constraints,
DEK deletion restriction and copied-key deletion cascade. Fixture blobs exercise
SQL integrity only; native tests separately verify actual signatures and HPKE.
